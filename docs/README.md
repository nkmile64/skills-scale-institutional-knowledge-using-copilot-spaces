# OctoAcme Project Management Docs

OctoAcme runs projects with a customer-first, iterative, and data-informed approach, with clear ownership across the team. Work moves through initiation, planning, execution, release, and retrospective: teams align on a real need and measurable outcomes, shape approved work into a prioritized backlog and milestones, deliver and track small increments, verify releases, and turn lessons into improvements.

The Project Manager coordinates schedules, risks, dependencies, and communication; the Product Manager defines outcomes, prioritizes work, and measures impact. Developers build and test against acceptance criteria, QA validates quality, and stakeholders provide input and approvals. Teams coordinate through standups, delivery and PM/Product Manager syncs, project boards, and regular stakeholder updates, escalating blockers through the PM, Product Lead, and sponsor as needed.

Quality is built into delivery through unit and applicable integration tests, CI checks for tests and linting, code review, security scanning, and manual QA where needed. Critical flows receive smoke tests, while releases require acceptance criteria to be met, passing CI and security scans, a rollback or mitigation plan, and post-deployment verification. Retrospectives after sprints, releases, milestones, or incidents capture actionable improvements with owners and follow-up.
